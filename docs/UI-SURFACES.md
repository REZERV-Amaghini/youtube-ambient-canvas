# 操作画面の濃さと対応範囲

操作画面の濃さは、ボタンや検索欄、チャット、メニューなどの背景を調整する設定です。種類別の濃さを0〜100%で設定し、全体の倍率0〜1を掛けます。初期値は各種類100%、全体の倍率1です。全体を0にすると、種類別の値を保ったまま完全に透明になります。背景映像の濃さとは独立しています。

個別に調整できるのは、ボタンと検索、カードとチャット、メニューとサイドバーの3種類です。設定画面には、種類別の値と乗算後の「適用」値を表示します。たとえばカードとチャット80%、全体0.5なら、適用値は40%です。従来の全体0〜100と補正-30〜30の保存値は、各種類の見た目を保つ形で読み取ります。保存するのは変更した項目だけです。古い保存内容は書き換えません。

## 設定画面の構成

再生バーでは、アンビエント背景のトグルとアイコンだけの歯車を並べます。トグルをOFFにしても設定は開いたまま操作でき、閉じた設定も歯車から開けます。設定画面は、社長が指定したiOS27をモチーフにします。透過する面と丸み、薄い境界線を使い、文字と操作状態の見やすさを保ちます。

| メニュー | 設定項目 |
| --- | --- |
| 背景の見た目 | 放射状モード、背景映像の濃さ、ぼかし、彩度 |
| 操作画面の濃さ | 全体の倍率、ボタンと検索、カードとチャット、メニューとサイドバー |
| 黒帯と描画 | 黒帯の除外と置き換え、採色範囲、背景のFPS |
| 安全と言語 | 高速点滅の警告、表示言語 |

説明はinfoボタンのホバー、キーボードフォーカス、クリックで表示します。クリックで固定した説明は、同じボタンをもう一度押すと閉じます。Escapeではフォーカスを動かさずに説明だけを閉じ、そのままホバーやフォーカスが続いても再表示しません。ボタンに入り直すと説明を表示します。

詳細ページの枠は項目数に合わせた固定の高さにし、説明を開いても説明ボタンが移動しないようにしています。狭いプレーヤーでは内容をスクロールでき、戻る操作と閉じる操作は上部に残ります。説明を閉じた後のEscapeでは設定一覧に戻り、元の項目へフォーカスを戻します。さらにEscapeで設定を閉じると、歯車へ戻ります。警告ダイアログには従来の暗い背景を使います。

修正前は、Tabで表示した説明をEscapeで閉じようとすると設定一覧へ戻り、説明ボタンを二度押してもホバー中は本文が残りました。現在は本文のhiddenとボタンのaria-expandedを一つの処理で管理し、表示をそろえています。

ローカルのブラウザでは、実際のキー操作とクリックで8件を確認しました。説明の開閉で背景の追加取得、描画、DOMの再走査が増えないことも、mainとWorkerの制御テストで確認しています。ホバーから説明本文へ移る動作は制御テストの対象で、今回のブラウザではマウス移動を検証していません。

説明の操作は[W3Cのホバー・フォーカス時の指針](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)と[Tooltip Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)を参考にしています。これらの確認は、サイト全体のアクセシビリティ適合を証明するものではありません。

今後の見た目も、このiOS27のモチーフにそろえます。[AppleのLiquid Glassの指針](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass)を参考に、操作部と設定にはガラス風の面を控えめに使います。縁と丸みをそろえ、透過やぼかしを何層も重ねません。長い本文には、文字を読みやすい背景を優先します。iOS27という指定は社長が選んだデザインの方針であり、Appleの特定バージョンの見た目を完全に再現したという意味ではありません。

警告を閉じると、直前に使っていた操作部へ戻ります。そのボタンが警告表示中に無効・非表示・削除になり、フォーカスを戻せない場合は設定の歯車へ移します。閉じるだけでは動画や背景映像の濃さを変えません。操作画面の濃さが0でも、警告の暗い不透明な面と背後の暗い背景は保ちます。戻り先の扱いは[W3Cのダイアログの指針](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)を参考にしています。

元のボタンが無効な場合、修正前のブラウザでは閉じた後にフォーカスが本文へ戻る不具合を確認しました。修正後は、通常・無効・非表示の戻り先と保存失敗時の再試行など、ローカルのブラウザで10件を確認しています。mainとWorkerの制御テストでは、親が非表示になる場合とボタンが削除される場合も対象にしています。見える映像は静止したままで、点滅検出には数値だけを渡しています。この確認で、実際の動画の検出精度や検出までの時間は検証していません。

背景映像の濃さは15%から100%、操作画面の濃さは全体の倍率0から1で管理します。保存された背景映像の濃さが0%や5%でも、読み込み時に下限の15%へ補正されます。警告の「濃さを下げる（15%）」はこの下限を使い、操作画面の倍率は変えません。日本語と英語、mainとWorkerで、この境界と65%からの変更を確認しました。

## 実装上の管理場所

設定の保存と範囲の検証、共通パレットの計算は[settings-store.js](../settings-store.js)の`YacSettingsStore.surfacePalette()`にあります。色と基本の見た目、各領域への適用は[ambient.css](../ambient.css)で管理します。[ambient.js](../ambient.js)は設定画面とチャットiframeへの反映を担当します。

パレットは設定を変更したときに更新します。各領域の基本の濃さに、種類別の割合と全体の倍率を乗算します。全体の倍率が0なら、背景、ぼかし、明暗の補正はなくなります。文字、SVG、フォーカス枠は保ちます。動画の各フレームやコメントの追加ごとに作り直す処理は加えていません。背景が何層も重なって濃くならないようにしています。

暗いテーマのメニューとガイドでは、文字の後ろの映像だけを暗くする補正も濃さに合わせて調整します。明るい映像に重なっても履歴や選択中の文字を読みやすくするためです。濃さ0では補正を解除し、元の文字色は変えません。

ダイアログは、対応する9種類のレンダラーとDialog Layoutを対象にします。新旧のPaper Dialogや、途中に別の枠が入る場合も、内側との塗りを重ねません。プレーヤーメニューは、明るいページテーマでも元の文字が白いため、暗い面を使います。選択やホバーでは背景を暗めに補正し、補足文字を読みやすくします。これらも全体の倍率と種類別の濃さを掛け、0なら塗りとぼかしを解除します。追加のDOM走査は使いません。

保存済みのCSSにあるホバー・クリックカードは、本文にだけ面を置きます。外枠、縁、矢印は同じ濃さに連動し、内側に二重の塗りを作りません。対応する説明ラベルも、塗り、ぼかし、影、矢印を連動させます。元の文字色とフェードのopacity、表示状態、操作の寸法は変えません。これらもCSSで適用し、DOM走査を追加しません。

タイトルから説明欄、コメント、関連動画の本文は、ぼかしのない面を一層だけ使います。長い本文やコメントごとに描画用のぼかしを増やさず、補足文字とリンクの色を保つため、基本の濃さは94%です。折りたたまれた説明欄のホバーとフォーカスでは、親のメタデータの面を98%にします。どちらにも「カードとチャット」の割合と全体の倍率を掛けるので、0なら透明になります。再生リストが入る関連動画の外側は、CSSで同期的に透明へ切り替えます。動画一覧の枠や、その内側の一覧部分に面を移し、再生中の行の祖先には塗りを重ねません。

画面の濃さと表示言語を変えても、背景映像を再取得したり、処理中のWorkerフレームを無効にしたりしません。背景の設定と警告の設定を変えたときは、従来どおり描画と検出を更新します。

アンビエントがOFFの間や、全画面表示中、タブが非表示の間は、DOM変更に対する背景領域の内部探索を省きます。再開時に一度だけ反映し、OFFでは元のテーマの背景を保ちます。警告の監視は、この探索とは別に管理します。制御テストでは12条件、ローカルのブラウザではmainとWorkerのON／OFFと再開を確認しました。実際のYouTubeのコメント読み込み時間は未計測です。

## 残る確認と未対応の領域

検索候補、対応するダイアログ、ミニガイド、タイトルとチャンネル、説明欄、コメント、関連動画の本文、プレーヤーメニュー、旧式のカードと説明ラベルはソース側で対応しました。保存済みのテーマCSSにあるクラスを参考にし、ローカル画面で確認した段階です。文字起こしも含め、現在のYouTubeとインストール済みのChrome・Firefoxでの確認は残っています。現在のプロフィールカードと、対応するクラスに一致しないダイアログには専用の調査が残ります。共通ボタンのクラスに一致する要素があっても、その領域全体への対応済みとは扱いません。

シアターモードで消えるチャットの純正アイコンは、実サイトで原因を確認する必要があります。代わりのアイコンを重ねて隠す方針は取りません。Enhancerのカラープリセットと、新旧両方のYouTube画面でも確認を続けます。

## 検証と仕様変更

旧式のカードと説明ラベルのローカル画面では、明暗テーマ、乗算、全体と種類別の濃さ0、OFFでの復元など110件の検査を通しました。入力内容、画像、操作の状態色、寸法、元のフェードと表示状態を保っています。最初の検査は、ブラウザがアルファ値0.172を0.173と表示する丸めで失敗しました。宣言した値の計算と、ブラウザが解決した実際の塗りを分けて検査し、最初の記録も残しています。

同じ画面の8枚では、明暗テーマと白黒背景の標準の濃さの32領域を画像から測定し、最小コントラストは4.541970:1でした。濃さ0のJPEGの32領域では、測定した背景画素との差は0でした。完全透過の厳密な証明には使いません。説明ラベルは元のopacityが1の状態で測り、フェード途中のコントラストは測定範囲に含めていません。現在のYouTubeのホバー処理や、すべてのプロフィールカードを検証した結果ではありません。

ダイアログのローカル画面では、10種類の表示を新旧2種類の外枠で確認し、それぞれ141件の検査を通しました。明暗テーマ、塗りを重ねないこと、全体と種類別の濃さ0、OFFでの復元、入力・画像・状態色の保持を含めています。キーボードでメニュー項目を移動・選択でき、フォーカス枠は濃さ0でもOFF時の元の枠と同じでした。

ダイアログとプレーヤーメニューの8枚では、通常行と選択行も含む標準の濃さの24領域を画像から測定し、最小コントラストは4.541970:1でした。プレーヤーの元のopacity 0.9を保ち、文字の合成には画像で確認したフィルター前の白黒背景を使っています。最初の選択行は2.937319:1で失敗したため、選択とホバーの背景を暗めに修正しました。元の画像と測定内容は残し、基準は下げていません。濃さ0のJPEGの24領域では、測定した背景画素との差は0でした。完全透過の厳密な証明には使いません。

タイトルとチャンネルを含む最新のローカル画面では、標準の濃さで明暗テーマと白黒背景の48件を画像から測定し、文字のコントラストは最小4.764497:1でした。新旧の画面と、再生リストが動画一覧の内側・外側にある場合は、各60件のCSSからの計算も確認しました。内側の説明欄と入れ子の一覧は透明に保ち、入力、アバター、サムネイル、状態色を変えていません。濃さ0のJPEGの48件では、測定した背景画素との差は0でした。JPEGは完全透過の厳密な証明には使いません。

旧画面への切り替え直後は、元の濃い塗りが更新まで残り、リンクのコントラストが4.42:1まで下がる不具合を確認しました。メタデータの枠の追加と、外部テーマによる塗りの変更は、監視処理で描画前に反映するよう修正しました。修正後は同じ切り替え直後の検証を通っています。コメントの追加や通常の再生で再走査を増やす変更は加えていません。

本文のローカル画面では、標準の濃さで明暗テーマと白黒背景の36件を画像から測定し、文字のコントラストは最小4.764497:1でした。別に、CSSから計算した48件、説明欄の新旧切り替え、入力内容とサムネイルの保持、OFF時の元の塗りへの復元、個別の濃さ0%を確認しました。濃さ0のJPEGの36件では、測定した背景画素との差は0でしたが、JPEGは完全透過を厳密に証明できません。最初の撮影では固定背景が長いページ全体を覆わず、測定領域の均一性検査も失敗しました。確認ページと測定位置を直して撮り直し、元の画像を残しています。基準は下げていません。
